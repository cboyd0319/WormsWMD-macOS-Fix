# v1.7.4 Release

Status: Active

## Problem

The post-1.7.3 audit fixes and final hardening pass are complete in the working
tree. Release-zip and bootstrap users need a new tagged v1.7.4 release with
updated documentation, changelog, and release assets.

## Scope and non-goals

In scope:

- Update v1.7.4 version strings, bootstrap refs, release examples, issue
  placeholders, and changelog.
- Build and validate a v1.7.4 release bundle.
- Preserve the release-tag bootstrap sequence: empty exact-commit pins in the
  tag commit, then a follow-up mainline commit with the exact tag hash.
- Record local validation and post-publication checks.

Out of scope:

- Replacing the Qt runtime archive.
- Changing runtime behavior beyond the audited v1.7.4 fixes.
- Rewriting existing release history.

## Constraints and risks

- Do not publish a release unless local validation passes.
- The release commit cannot contain its own commit hash, so bootstrap exact
  commit pins stay empty until after the tag exists.
- Keep downloads HTTPS-only and checksum-verified.
- Preserve save data, game-bundle backup/rollback behavior, and macOS 26+
  compatibility.

## Surprises & Discoveries

- The tag commit must keep exact bootstrap commit pins empty; the mainline
  follow-up commit pins `install.sh` and `Install Fix.command` after the tag
  target hash exists.

## Decision Log

- Use the v1.7.3 release pattern: tag v1.7.4 with empty commit pins, verify
  release assets, then pin mainline bootstrap installers to the exact tag
  target.
- Pin GitHub-hosted CI runners to stable explicit image labels instead of
  `*-latest`: `ubuntu-24.04` for Linux checks and `macos-26-intel` for macOS
  checks that validate the x64 game/runtime path.

## Outcomes & Retrospective

v1.7.4 was published with checksum and GitHub artifact attestation. The
follow-up mainline commit pins bootstrap commit verification to the exact
release tag target. A post-publication hardening pass also pinned CI runner
labels, updated GitHub Actions to latest stable full-SHA refs, pinned the
ShellCheck binary version used by CI, and required explicit Qt versions when
writing new Homebrew bottle locks.
