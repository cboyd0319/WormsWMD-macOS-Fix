# v1.7.6 Release

Status: Completed

## Problem

Issue #20 and the subsequent repository-wide integrity audit are complete on
`main`, but release-zip and bootstrap users still receive v1.7.5. A v1.7.6
patch release must publish the corrected GOG dependency handling, complete
rollback coverage, rebuilt Qt payload, and adjacent fail-closed hardening.

## Scope and non-goals

In scope:

- Update deterministic version, bootstrap, documentation, issue-template, and
  changelog surfaces to v1.7.6.
- Build and validate the v1.7.6 release bundle.
- Commit and push the release, tag and publish v1.7.6, verify the published
  checksum and attestation, and confirm it is the latest release.
- Pin mainline bootstrap and Qt payload verification to the exact tag commit in
  a follow-up commit.
- Reply to issue #20 only after publication verification succeeds.

Out of scope:

- Further product behavior changes after the completed issue #20 audit.
- Rewriting existing release history.

## Constraints and risks

- The release commit cannot contain its own commit hash. Exact bootstrap commit
  pins must be empty in the tag commit and added on `main` after publication.
- Do not publish or reply to the issue unless local and hosted verification
  succeeds.
- Release downloads remain HTTPS-only, checksum-verified, and attested.
- Preserve rollback, save data, macOS 26+, and repository behavior on Windows.
- Avoid redundant hosted runs: reuse the final PR evidence, require one release
  commit CI run, and do not request another Copilot review.
