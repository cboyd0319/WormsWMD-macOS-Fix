# v1.7.0 Pre-Release Prep

Status: Active

## Problem

The issue-10 bug hunt and supply-chain hardening pass are complete. The repo now
needs deterministic pre-release updates for v1.7.0 before the final release
commit, tag, and GitHub release publication steps.

## Scope and non-goals

- Update version surfaces, changelog, release docs, and validation references
  that do not require the final release commit hash.
- Keep the new Qt 5.15.19 artifact, checksum, and source provenance in the
  release bundle.
- Record the release-tag and post-release bootstrap pin sequence.
- Do not invent the final bootstrap commit hash before the release tag exists.
- Do not rotate secrets in this pass.

## Constraints and risks

- Bootstrap installers on `main` must remain exact-commit pinned for public
  release.
- The v1.7.0 tag cannot contain a self-referential commit pin. Match the prior
  release pattern: tag the release with empty commit pins, then make a
  follow-up `main` commit pinning the bootstrap installers to the tag target.
- User-facing docs should not claim a published GitHub release exists before it
  is actually published.

## Surprises & Discoveries

- The v1.6.6 tag itself had empty bootstrap commit pins; `main` was pinned to
  the v1.6.6 tag target in the next commit. The v1.7.0 release should use the
  same sequence.

## Decision Log

- Do not replace the final release commit hash with a guessed value. The public
  `main` bootstrap commit pins need one last update after the v1.7.0 tag exists.
