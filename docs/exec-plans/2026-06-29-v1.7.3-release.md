# v1.7.3 Release

Status: Active

## Problem

The issue #12 hardening has merged to `main`, but release-zip users still get
v1.7.2 until a new tagged release publishes fresh assets.

## Scope and non-goals

In scope:

- Update v1.7.3 release surfaces, version strings, bootstrap refs, changelog,
  and verification docs.
- Run local release validation.
- Tag and push `v1.7.3`.
- Verify the GitHub release assets and then pin mainline bootstraps to the
  exact v1.7.3 tag commit.

Out of scope:

- Replacing the Qt runtime archive.
- Changing runtime behavior beyond release-surface edits.
- Rewriting existing release history.

## Constraints and risks

- Do not publish a release unless validation passes.
- The release-tag commit cannot contain its own commit hash, so bootstrap
  commit pins stay empty in the tag and are filled in a follow-up `main`
  maintenance commit.
- Keep downloads HTTPS-only and checksum-verified.
- Preserve the v1.7.2 historical release notes and plans.

## Milestones

- [ ] Milestone 3: Tag and push v1.7.3, then verify release assets.
- [ ] Milestone 4: Pin mainline bootstraps to the v1.7.3 tag commit.
