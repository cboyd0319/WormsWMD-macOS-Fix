# v1.7.5 Release

Status: Completed

## Problem

Issue #19 is addressed in the working tree, but release-zip and bootstrap users
still receive v1.7.4. A v1.7.5 patch release must publish the fix, become the
latest GitHub release, and give the reporter a verified build to retry.

## Scope and non-goals

In scope:

- Update deterministic version, bootstrap, documentation, issue-template, and
  changelog surfaces to v1.7.5.
- Build and validate the v1.7.5 release bundle.
- Commit and push the release, tag and publish v1.7.5, verify the published
  checksum and attestation, and confirm it is the latest release.
- Pin mainline bootstrap verification to the exact tag commit in a follow-up
  commit.
- Reply to issue #19 only after publication verification succeeds.

Out of scope:

- Replacing the Qt archive or changing its checksum.
- Closing issue #19 before the reporter confirms the release on macOS 26.6.
- Rewriting existing release history.

## Constraints and risks

- The release commit cannot contain its own commit hash. Exact bootstrap commit
  pins must be empty in the tag commit and added on `main` after publication.
- Do not publish or reply to the issue unless local and hosted verification
  succeeds.
- Release downloads remain HTTPS-only, checksum-verified, and attested.
- Preserve rollback, save data, macOS 26+, and repository behavior on Windows.

## Decision Log

- Follow the established two-commit release sequence: empty exact pins in the
  tag commit, then immutable pinning on main after the tag hash exists.
